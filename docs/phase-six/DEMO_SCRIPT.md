# BurnLens fixed demo script

This script presents the exact Phase Six local pre-publication surface and its
immutable evidence. It does not authorize publication, deployment, access
changes, public sharing, or external submission.

## Before the demo

1. Use a clean repository checkout at the exact candidate commit.
2. Validate the Phase Six surface manifest.
3. Validate both forms of the Phase Four package.
4. Open
   `samples/runs/phase-six/burnlens-baseline-first-portfolio-surface-v0.1.0/index.html`
   locally or through a loopback server.
5. Confirm the warning is visible before interpreting any result.

Stop if the surface, any exact evidence target, the package validator, or the
warning fails.

## 30-second route

Say:

> BurnLens is an experimental CV-to-GEOINT portfolio project. It trains and
> evaluates a bounded U-Net, but the model predicts every selected test core as
> burned and loses to the RBR baseline. BurnLens rejects the model, carries RBR
> into one Ward Creek geospatial workflow, and keeps WCP-002’s 66.76-hectare
> false-positive-risk result visible. This is not official, operational, or
> emergency information.

Actions:

1. Show the hero and warning.
2. Show RBR `1.000` beside U-Net `0.299`.
3. Show WCP-001 beside WCP-002.

## 2-minute route

Complete the 30-second route, then:

1. Open the exact Ward Creek interface.
2. Keep **Accepted RBR** visible.
3. Focus WCP-001 and state: 141.44 ha; 94.19% MTBS overlap.
4. Focus WCP-002 and state: 66.76 ha; 0% MTBS overlap; visible
   false-positive-risk evidence.
5. Turn **Rejected U-Net** on only as a diagnostic, then turn it off.
6. Return to the Phase Six surface and show the seven-step evidence chain.
7. Open the two medium known issues and state their bounded impact and
   workaround.

Close with:

> The portfolio result is the governed evidence path and honest rejection,
> not a claim that the model won.

## 5-minute route

Complete the 2-minute route, then:

1. Open the exact baseline evaluation and point to the selected-core scope.
2. Open the exact model decision and point to the all-burned prediction
   failure.
3. Show the trace table: software, AOI, label schema, label set, dataset,
   split, baseline, model, accepted run, and package hashes.
4. Open the Phase Five index and show recovery, assurance, reconstruction,
   rollback, and known-issue links.
5. Explain the source boundary:
   - Sentinel-2 is optical evidence under Copernicus attribution;
   - MTBS is analyst-interpreted reference context;
   - TNM layers are context, never access or safety authority;
   - owner-approved regions are not independent ground truth.
6. Show the reproduction commands in `REVIEWER_JOURNEY.md`.
7. End on the limitations section, not the metric.

## Questions to answer precisely

| Question | Answer |
|---|---|
| Did the model work? | It trained, evaluated, and reproduced, but failed the comparison and was rejected. |
| Why use RBR? | It was the preregistered validation-selected baseline and was stronger on the bounded selected-core test. |
| Is Dice 1.0 general performance? | No. It is limited to 89 selected prototype test cores across two events. |
| Is WCP-002 a mistake? | It is retained false-positive-risk evidence showing the accepted baseline’s limit. |
| Are the labels ground truth? | No. They are owner-approved prototype regions with non-owner gates and explicit unknown rings. |
| Is this operational? | No. It is a local, offline, experimental portfolio artifact. |
| What would come next? | A separately governed follow-on experiment could address the rejected model, but it is outside this project. |

## Demo failure behavior

Do not improvise around a missing or mismatched artifact. Preserve the failure,
state which gate failed, and use the exact immutable package or record to
diagnose it. Never substitute a screenshot for a failed live surface or imply
that a partial demo passed.
